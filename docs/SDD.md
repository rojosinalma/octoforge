# Octoforge — software design document

## Purpose

Octoforge is the home of a family of self-hosted GitHub tools. It gives them one place to be found,
one list of every tool, and a small app for the jobs that span tools:
an index with live status, creating and handing over GitHub credentials, and hosting the tools'
databases next to each other.

## Architecture

- A git repository. Each tool (a **member**) has its own repository, history, CI, releases,
  container image and URL. A local clone of a tool may sit at the top level (`<tool>/`); that folder
  is git-ignored here, and the tool keeps its `compose.yaml` at its own root, so it runs the same
  from `octoforge/<tool>` as from a clone anywhere else. Octoforge never pins a tool's version.
- `members.json` is the machine-readable index (`name`, `repo` as `owner/name`, optional `homepage`
  per member), validated by a zod schema in `packages/shared`; `README.md` is the human index.
  `bin/verify` keeps both consistent and scans tracked files for leaks. The server reads
  `members.json` at start-up (an invalid or missing file stops it with the reason) and again when
  its mtime changes; an invalid edit later keeps the last good list and logs a warning.
- The app is one container (`ghcr.io/rojosinalma/octoforge`), a Bun workspace:
  - `packages/shared`: zod schemas of the member contract (`octoforge.json`, status answers), the
    settings schema, API types, and pure builders (GitHub App manifest, token form URLs, `.env` block).
  - `packages/server`: Hono on Bun, port 3000. Routes orchestrate; logic lives in `src/lib`
    (member registry, member API client, GitHub client, credentials, database adoption, secret store,
    settings, journal); `src/db` holds the SQLite and Postgres drivers and their migrations.
  - `packages/web`: React + Vite + tailor-react, served by the server as a static SPA. tailor-react is
    the React kit of the tailor design system, vendored as source in `vendor/tailor-react` (a workspace);
    its CSS, skins, palettes and icon sprite are vendored in `packages/web/public/tailor/`.
- The member contract is [members.md](members.md). Octoforge reads manifests and status from each
  member's `/api/octoforge/*`, and writes to members only through that API, never through a database.

## Data model

Octoforge's own database: SQLite at `DATA_DIR/octoforge.db` by default, or Postgres when
`DATABASE_URL` is a `postgres://` URL (tables in schema `forge`). Migrations live in
`packages/server/src/db/migrations/{sqlite,postgres}`, generated by drizzle-kit from the twin schema
files, additive only, applied at start-up.

| Table | Holds |
|---|---|
| `settings` | key/value (JSON) rows over the defaults of the settings schema; read at use time. Row `shared_app` (outside the schema) holds the shared App's non-secret facts |
| `instances` | member, base URL, optional public URL, label: where each member runs and where GitHub reaches it |
| `deliveries` | time, member, target (instance URL or `env block`), kind (`app`, `pat`), ok, message, detail |
| `adoptions` | time, member, target, engine (`postgres`, `sqlite`, `release`), ok, message, detail |
| `created_roles` | cluster (host:port of the admin URL), role, `pg_roles.oid`, time: the Postgres roles Octoforge created, the only ones it may give a new password |

No table holds a credential, a private key, a token or a database password. Details carry only
non-secret facts (App slug and id, token login, redacted URLs, table row counts).

**Memory only**: the secret store holds an App's private key and webhook secret, a pasted token, a
generated or existing role password and the `state` of a manifest flow. Entries expire after `secretTtlMin`
(default 15 min), the store holds at most `secretStoreMax` entries, delivery removes them, and the
API never returns them except in the one-time `.env` block.

## Flows

- **Clone**: `git clone` gets the app and `members.json`; each tool is cloned on its own, next to
  it or anywhere else, and updated in its own folder.
- **Index**: for each `members.json` entry, the manifest comes from the first configured instance
  (`GET /api/octoforge/manifest`), else from `raw.githubusercontent.com/<owner>/<repo>/HEAD/octoforge.json`,
  cached for `manifestCacheMin`. Each instance is probed on the manifest's `health` path. A member
  without a manifest still gets a card from its name and homepage.
- **GitHub App**: Octoforge builds the App manifest from the member's `github.app` plus the name,
  homepage, hook URL (the instance's public address + `webhook_path`), `setup_url` and `redirect_url`
  (`PUBLIC_URL/github/callback`), keeps a random `state` in memory and lets the browser post the
  manifest to GitHub (personal account or organisation). The callback checks the `state` (single
  use), exchanges the code at `POST /app-manifests/{code}/conversions`, keeps the key and webhook
  secret in memory and shows the install link. "Find installations" lists them with an App JWT.
  **Deliver** sends `PUT /api/octoforge/github` to each picked instance; the secret is dropped once
  every target took it.
- **Shared GitHub App**: "Use an existing App" takes the App id and key, signs a JWT and reads
  `GET /app` and `GET /app/installations`; "Create the shared App" posts a manifest built from the
  union of every member's `github.app` (the callback recognises the shared flow by its `state`).
  The page shows a permission matrix (App granted, each installation accepted, each member needs),
  links GitHub's permission and installation pages for each gap, and delivers the App to every
  picked instance of every App member. Members may report their own definite gaps in
  `/status.github.missing`.
- **Token**: Octoforge links GitHub's pre-filled token forms (classic: scopes + description;
  fine-grained: name, description, expiry, owner, one parameter per permission). A pasted token is
  checked with `GET /user`; for classic tokens `X-OAuth-Scopes` is compared with the required scopes
  (implied scopes expanded) and missing ones are shown before delivery.
- **Fallback**: instead of delivering, the credential can be shown once as an `.env` block with the
  variable names from the manifest's `env`; Octoforge forgets it at the same moment.
- **Database adoption (Postgres)**: with `FORGE_PG_ADMIN_URL`, Octoforge creates the login role
  `<member>` (and records its oid in `created_roles`), rotates its password when the recorded oid
  matches, or, for a role it did not create, keeps the password the operator entered after logging
  in with it once; without one it refuses. It then creates schema `<member>` owned by the role, sets
  its `search_path` in the shared database only, creates `octoforge_reader` and grants it `USAGE` +
  `SELECT` (also on future tables), all in one transaction. It then calls
  `POST /api/octoforge/database/adopt` on the first instance with `copy: true` and, when that
  worked, on the others with `copy: false`. The password lives only for that call.
- **Database adoption (SQLite)**: with `OCTOFORGE_SHARED_DATA`, the URL is `sqlite:<dir>/<member>.db`.
- **Release**: `DELETE /api/octoforge/database` (or `/github`) on one instance; logged.
- **Sibling list**: Octoforge builds one list (itself at `PUBLIC_URL`, then one entry per member with
  an instance: the first instance's public URL, else the `public_url` it reports, else its base URL,
  the manifest `title` and an absolute `icon`) and sends it with `PUT /api/octoforge/siblings` to
  every instance of every member: shortly after start-up, after each instance add, change or
  removal, every `siblingsResendMin` minutes and on "Send sibling list now". One run at a time (a
  trigger during a run queues one more), a few calls in parallel, each with the request timeout. A
  404 marks the instance "not supported" in memory until an instance changes, a manual send or a
  restart. A removed instance first gets `DELETE /api/octoforge/siblings` (best effort). Without
  `OCTOFORGE_TOKEN` or `PUBLIC_URL` nothing is sent, and the reason is logged once. Each run logs
  one summary line; each call is logged at debug. The members page shows the last outcome per
  instance.

## Configuration surface

Bootstrap values and secrets come from the environment ([configuration.md](configuration.md)):
`AUTH_PASSWORD` or `AUTH=none` (one is required), `OCTOFORGE_TOKEN`, `PUBLIC_URL`, `SESSION_SECRET`,
`DATABASE_URL`, `FORGE_PG_ADMIN_URL`, `OCTOFORGE_SHARED_DATA`, `LOG_LEVEL`, `PORT`, `DATA_DIR`,
`WEB_DIST`, `MEMBERS_FILE`. Everything tunable is a row in `settings`, edited on the Settings page.
`bin/verify` reads optional extra leak patterns from `.git/info/leak-patterns` (path overridable
with `OCTOFORGE_LEAK_PATTERNS`).

## Security

- Fail closed: the server exits at start-up unless `AUTH_PASSWORD` is set, or `AUTH=none` is set on
  purpose for a proxy that authenticates in front. Both at once is refused too.
- Login issues a signed, HttpOnly, SameSite=Lax cookie; `/api/*` and the App callback require it.
  `/health` is the only open route besides the login.
- Member calls carry `Authorization: Bearer <OCTOFORGE_TOKEN>`; the same value is set on every member.
- The logger redacts any field whose name looks like a secret, and request logs carry the path only
  (the callback query holds the one-time code). Every outgoing call is logged as method, target and
  outcome.
- Postgres DDL cannot take parameters: member names are validated against the member-name pattern
  and a reserved list, identifiers and literals are quoted, and the generated password is hex. An
  existing role's password never goes into SQL text: it is only used to log in once and placed in
  the member URL.

## Design decisions

|---|---|---|---|

| Index source | `.gitmodules` `homepage` key + README table, checked by `bin/verify` (superseded 2026-10-22) | No extra manifest format; git already parses `.gitmodules` | 2026-10-21 |
| Language | Bash for `bin/verify` | Only git and text checks; no runtime to install | 2026-10-21 |
| Runtime | No container | Nothing to serve yet; a root `compose.yaml` arrives with the first shared feature | 2026-10-21 |
| Versioning | None for the umbrella | The tools version themselves; the umbrella's state is the set of pointers on `main` | 2026-10-21 |
| Dependency updates | Dependabot `gitsubmodule` + `github-actions`, weekly | Keeps pointers and actions current through reviewed pull requests | 2026-10-21 |
| Dependency updates | Dependabot `github-actions` only, weekly (supersedes the row above) | No pinned tool versions are left to bump | 2026-10-22 |
| Licence | AGPL-3.0 | Same as the tools | 2026-10-21 |
| Runtime | One container: Bun + Hono server serving a React + Primer SPA (supersedes "No container") | The index, credentials and database features need a server and a UI; Primer matches the members' UI | 2026-10-21 |
| Language | TypeScript for the app; bash stays for the index checks in `bin/verify` (supersedes "Bash for `bin/verify`" as the only language) | Same stack as the members; shared zod schemas between server and UI | 2026-10-21 |
| Database | SQLite by default, Postgres optional (schema `forge`); member databases one schema per member on Postgres or one file per member in a shared directory; no secrets stored | Zero setup by default; one shared database when several members run; each member keeps owning its tables | 2026-10-21 |
| Credential delivery | Through each member's API (`PUT /api/octoforge/github`, bearer `OCTOFORGE_TOKEN`); a one-time `.env` block as fallback | No credential ever lands on disk in Octoforge; members without the API still get a copyable result | 2026-10-21 |
| Secrets | Memory only, with a TTL and a size cap from settings, dropped on delivery | A credential exists in Octoforge only for the minutes between creation and hand-over | 2026-10-21 |
| Public address of an instance | Optional `public_url` per instance, else the member's reported `public_url` in `/status` (optional field, contract stays 1), else the base URL | The base URL is where Octoforge calls the member, often a private name; GitHub needs an address it can reach for webhooks and the setup page | 2026-10-21 |
| Existing member roles | Keep the password of a role Octoforge did not create (operator enters it, checked by a login first); rotate only roles recorded in `created_roles` by oid; `search_path` set `IN DATABASE` | A member may already use its role for its own database: a new password would break its `DATABASE_URL` and the rollback; a cluster-wide `search_path` would change it there too | 2026-10-21 |
| GitHub App | One shared GitHub App for all members (2026-10-21): an existing App is registered by id + key (key in memory only; id, slug, owner, permissions and installations kept in `settings` row `shared_app`), or created from the union of every member's `github.app` (highest level wins, one `webhook_path` at most); gaps closed on GitHub's permission and installation pages, then re-checked with `GET /app`. Per-member Apps stay as the alternative | One key, one set of installations and one place to change permissions for every tool; GitHub has no API to change an App's permissions, so Octoforge shows the exact gaps and links the pages | 2026-10-21 |
| Sibling list pushed by Octoforge (2026-10-21) | Octoforge pushes the family list to every instance (`PUT /api/octoforge/siblings`) on changes, at start-up and every `siblingsResendMin`; outcomes kept in memory only, a 404 stops the pushes to that instance until an instance changes | Members never need to know where Octoforge or the other tools run; a restarted member gets the list back by the next push; no new table and no polling from the members | 2026-10-21 |
| UI on tailor-react (2026-10-21) | React + tailor-react (`Ui.*` components) over the tailor CSS, every tailor skin and palette, skin `primer` and palette `gruvbox` by default, mode `auto`; the choice is stored as the settings `skin`, `palette` and `mode` (supersedes Primer React and the `theme` setting) | One look across the house tools, and every skin and palette with a sun/moon toggle in the footer instead of the eight Primer themes; the `primer` skin keeps the GitHub look. The kit is vendored as source, so a fresh clone and the image build need nothing outside the repo | 2026-10-21 |
| Auth | Fail-closed password login (`AUTH_PASSWORD`), `AUTH=none` only on purpose | The app creates credentials; it must never start open by accident | 2026-10-21 |
| Members | Listed in `members.json` (name, repo, homepage), tools are git-ignored folders, no submodules (supersedes the submodule model and `.gitmodules` as the index) | Each tool is cloned and updated on its own; pointer bumps added work without value, and a fresh clone of Octoforge builds and verifies without any tool | 2026-10-22 |

## Current scope

The index with live health, GitHub App and token creation with delivery to every instance of a
member, the sibling list for the tool switcher on every instance, and adoption of member databases into a shared Postgres database or SQLite directory.
Views that span members read through `octoforge_reader`; writes always go through the member APIs.

## Operations

`bin/verify` locally and in CI. The app's health endpoint, logs, data and upgrades are described in
[operations.md](operations.md); each tool documents its own operations.
